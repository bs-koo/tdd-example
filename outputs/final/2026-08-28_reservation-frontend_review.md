## 1. 총평

### 1.1 축 A 총평 — 전략 일치

**전략 §2가 새로 수립한 톤 기준(SSOT)이 코드에 한 글자도 어긋나지 않고 옮겨졌다.** `tokens.css` 의 색 hex 26개, 타이포 5단, 간격 8단, 라운드 5단, 그림자·모션 값이 전략 §2와 완전히 일치한다. `app.css` 810줄에 리터럴 색이 **0건**이고 전부 변수 참조다 — 톤 기준을 SSOT로 세운다는 목표가 실제로 성립했다.

§1.5의 세 가지 기술적 도박(`display:contents` 그리드, `grid-auto-flow:column` 축 전환, 연속 칸 `visibility:hidden`)이 **셋 다 실물에서 작동한다.** 특히 축 전환은 방 이름을 두 번 렌더하지 않고 390px에서 회의실 4곳을 가로 스크롤 없이 세웠다 — B-24 제약과 성공 기준 5의 정면 충돌을 DOM 하나로 푼 것이 이 산출물에서 가장 값진 판단이다.

저작권 가드는 **위반 0건**이다. 토스 문자열·브랜드 hex·전용 서체·이미지 자산이 코드에 하나도 없다(§2.5 실증).

깎이는 지점은 두 종류다. 첫째, **`vite.config.ts`가 브리프 §4 범위 밖에서 무단 변경**되어 개발 프록시가 백엔드 기본 포트와 어긋났다(Major). 둘째, 전략이 명시한 세부 결정 몇 건(과거 날짜 안내 문구, 범례 3종 구성, 모바일 열 폭, `--r-full` 배정)이 근거 기록 없이 이탈했다.

### 1.2 축 B 총평 — 완성도

개선 전 실물과 나란히 놓으면 차이가 논쟁의 여지 없이 크다. 좌상단 450×130px에 몰려 있던 무텍스트 알약 72개가, 시간 축을 갖고 열이 정렬된 격자로 바뀌었고, 방 이름 옆에 정원·층이 붙었고, 3칸 연속 예약이 **하나의 면**으로 이어져 "하나의 회의"로 읽힌다. 폼·취소창·오류 상태 모두 실물로 확인했고 렌더 결함(폰트 폴백·잘림·오버랩)은 없다. 안티-텔 §1·§2 위반도 0건이다 — 이번에는 "장식이 없어서"가 아니라 장식을 놓고도 지켰다.

그러나 **Critical 1건이 남는다.** 서버가 예약을 거절하는 순간 — 즉 오류 문구가 가장 필요한 순간 — 오류 배너가 모달 오버레이 **아래**에 그려지고, 다이얼로그 패널이 문장을 세로로 잘라내며, `다시 시도`·`알림 닫기` 버튼이 클릭·Tab 양쪽에서 도달 불가능해진다. 이것은 A-3(입력 보존)이라는 이번 작업의 성과와 정면으로 충돌한다 — 전체 문구를 읽으려면 다이얼로그를 닫아야 하고, 닫는 순간 보존된 입력이 사라진다.

기계 바닥에서도 두 건이 걸린다. 이번에 새로 넣은 정보 텍스트 4종(시간 축·정책·정원층·스탬프)이 **WCAG AA 미달(3.09:1 / 2.83:1)**이고, 슬롯 3상태의 면 대비가 **1.06–1.17:1**로 WCAG 1.4.11(3:1)의 1/3 수준이다. 전략 §2.2가 택한 "채도 없이 면의 밝기로만 구분한다"는 원칙 자체는 옳으나, 배정된 값이 그 원칙을 지탱하지 못한다.

### 3.2 Critical Issues (축 B) — 1건

#### B-Critical-1 [Critical] 서버 거절 오류가 모달 오버레이 **아래**에 그려진다 — 문구가 잘리고 복구 버튼이 죽는다

  - 패널 오른쪽(x≈1156–1340)의 `다시 시도` · `알림 닫기` 버튼도 실측 `150,154,161` — 역시 오버레이 아래다.
- **코드 근거**: `.overlay { position: fixed; inset: 0; z-index: 40; background: var(--c-overlay) }`(app.css:522-531). `.notice` 는 `z-index` 도 `position` 도 없다(app.css:293-300). `grep "position:" app.css` → `sticky` 0건, 상승 컨텍스트 없음.
- **도달 불가능성 2중**:
  1. **포인터** — `.overlay` 에 `pointer-events:none` 이 없으므로 전체 화면을 덮은 이 면이 클릭을 가로챈다. `다시 시도`·`알림 닫기` 를 누를 수 없다.
  2. **키보드** — `useDialogFocus.ts:47-66` 의 Tab 트랩이 초점을 패널 안에 가둔다. 두 버튼에 Tab으로 닿을 수 없다.
- **A-3과의 충돌 — 이 결함이 Critical인 이유**: 전체 문구를 읽는 유일한 방법은 다이얼로그를 닫는 것인데(`닫기` 또는 Escape), 닫으면 `setFormTarget(null)` 로 컴포넌트가 언마운트되어 **보존된 입력이 사라진다**(`ReservationPage.tsx:227`). 즉 이번 작업이 A-3에서 얻은 것과 A-8에서 얻은 것을 사용자가 **동시에 가질 수 없다.** 둘 중 하나를 버려야 한다.
- **개선 전보다 나빠진 지점**: 리디자인 이전에는 오버레이가 없어 배너가 완전히 읽혔다(`before-*.png` 구조). 모달화(B-11 해결)가 A-8의 배치 결함을 **악화시켰고**, 그 사실이 어느 문서에도 기록되지 않았다.
- **성공 기준 영향**: 브리프 §3-3 *"실패 시 무엇을 고쳐야 하는지 화면이 말한다"* 가 **가장 흔한 실패 경로에서 미충족**이다. 문구는 렌더되지만 사용자에게 전달되지 않는다.

- **조치 (택1, 둘 다 제약 안에서 가능)**
  - (a) `ReservationFormDialog` · `CancelConfirmDialog` 에 `errorCode?: string | null` optional prop을 추가하고, 패널 안에 `role` 없는(또는 `role="status"`) 오류 블록으로 렌더한다. 오류가 발생한 지점과 표시 지점이 같아져 진단 A-8의 본래 지적까지 닫힌다.

- **조치**: `--c-text-3` 을 `#8c93a1`(상대 휘도 L≈0.290) 에서 내린다. 흰 카드 위 4.5:1에는 L≤0.1833(≈`#6E7480`)이면 충분하지만, 정책 안내·스탬프는 페이지 배경 `#f4f5f7` 위에 놓이므로 **L≤0.1641(≈`#6A7080`)** 이어야 두 배경 모두에서 통과한다(실측 검증: `#6A7080` → 흰 배경 4.95:1 / 페이지 배경 4.54:1). 토큰 1개 수정으로 위 7개소가 동시에 해결되며, `--c-text-2`(`#5a6070`, 6.28:1)와의 위계 차도 유지된다.

#### B-Major-2 [Major] 슬롯 3상태의 면 대비가 1.06–1.17:1 — 범례에서는 가용/지난 시간이 사실상 구별되지 않는다

- **실측 (`after-reserved.png`)**: 가용 `255,255,255` / 지난 시간 `247,248,250` / 점유 `235,237,241`. 보더는 각각 `228,231,236` / `237,239,242` / `218,222,229`.
- **대비 계산**
  | 구분해야 할 쌍 | 대비 | WCAG 1.4.11 요구 |
  |---|---|---|
  | 가용 ↔ **지난 시간** | **1.06 : 1** | 3:1 |
  | 지난 시간 ↔ 점유 | **1.10 : 1** | 3:1 |
  | 가용 ↔ 점유 | **1.17 : 1** | 3:1 |
  | 가용 슬롯 보더 ↔ 카드 표면 | **1.24 : 1** | 3:1 |
- **눈으로 확인한 것**: `after-1440.png` 에서 09:00–16:00 구간(지난 시간)과 16:30–17:30 구간(가용)이 **큰 덩어리로 나란히 있을 때는** 회색기/흰색으로 구별된다. 문제는 두 곳이다.
  1. **범례** — 14×14px 스와치에서 `가용`(흰 면)과 `지난 시간`(`#f7f8fa` 면)은 1.06:1 차이를 14px 안에 담아야 한다. 실물에서 두 점은 거의 같아 보인다. 상태 학습의 출발점인 범례가 상태를 가르치지 못한다.
  2. **단독 칸** — 지난 시간 슬롯과 가용 슬롯이 인접하지 않은 경우(예: 예약이 흩어진 날), 개별 칸만 보고 "이건 눌러도 되는가"를 판단할 시각 단서가 1.06:1뿐이다.
- **중복 부호화는 어디까지 있나**: 점유 칸은 텍스트를 갖고 접근 이름에 예약자·목적이 실린다 → 점유는 안전하다. 지난 슬롯도 접근 이름에 `지난 시간` 이 들어간다 → 스크린리더 사용자는 안전하다. **위험한 조합은 "시각 사용자 × 가용 vs 지난 시간"** 하나이며, 이 조합에서 유일한 단서가 1.06:1이다.
- **전략과의 관계**: 전략 §2.2의 원칙(*"채도를 쓰지 않고 면의 밝기와 보더 대비로만 구분"*)은 옳다. 배정된 값이 그 원칙을 실행하기에 너무 붙어 있을 뿐이다.
- **조치**: `--c-past-bg` 를 `#f7f8fa` → `#EDEFF2` 수준(이미 `--c-surface-sunken` 으로 존재)으로 내리고 `--c-busy-bg` 를 한 단 더 내려 세 면의 서열 간격을 벌린다. 또는 지난 슬롯에 보더 `dashed` 등 밝기 외 채널을 하나 더 준다(칸 병합·노드 제거가 아니므로 제약과 무관하다).

#### B-Major-3 [Major] 격자가 가로로 스크롤되면 방 이름 열이 화면 밖으로 나간다 — 어느 행이 어느 방인지 사라진다

- **실물 근거 (`after-1024.png`)**: 보드 카드 하단에 가로 스크롤바가 있고, 시간 축의 마지막 열이 `17:0` 에서 잘려 있다(17:30 열은 완전히 화면 밖).
- **코드 근거**: `.board-card { overflow-x: auto }`(app.css:343-349). `grep "position:" app.css` → **`sticky` 0건.** `.board__room` · `.board__corner` 어디에도 고정 선언이 없다.
- **귀결**: 1024에서 오른쪽으로 스크롤해 17:00·17:30을 보려 하면 방 이름 열(`--room-col: 148px`)이 왼쪽으로 밀려나 사라진다. 그 순간 화면에는 이름 없는 4개 행만 남는다. 진단 B-18이 지적한 *"폭이 줄면 방↔시간 대응이 소실된다"* 의 다른 형태다.
- **성공 기준 5와의 관계**: 기준 5는 *"방 × 시간 정렬이 유지된다"* 이고 정렬은 유지된다(`display:contents`가 보장). 이것은 정렬이 아니라 **가독의 문제**이므로 기준 5를 깨뜨리지는 않는다. 그래서 Critical이 아니다.
- **조치**: `.board__corner`, `.board__room` 에 `position: sticky; left: 0; background: var(--c-surface); z-index: 1` 을 준다. `display:contents` 행 안의 그리드 항목이므로 sticky가 정상 동작하고, 마크업 변경이 없어 모든 제약과 무관하다.

### 3.4 Minor Issues (축 B) — 6건

#### B-minor-1 폼 검증 실패가 키보드·스크린리더 사용자에게 무반응으로 보인다
`ReservationFormDialog.tsx:100-103` — `확인` 클릭 시 검증에 걸리면 `setAttempted(true)` 만 하고 반환한다. 오류 문구는 `role` 없는 `<span>` 에 `aria-describedby` 로만 연결되며(`:152-156`, `:190-194`), **라이브 리전도 초점 이동도 없다.** 초점은 `확인` 버튼에 남으므로 스크린리더는 아무것도 읽지 않고, 화면을 못 보는 사용자에게는 버튼이 죽은 것처럼 느껴진다. `role="alert"` 는 하드 제약이 막지만 **`role="status"` 는 허용 목록에 있었고**(전략 §7) 쓰이지 않았다. 첫 번째 무효 필드로 `focus()` 를 옮기는 것만으로도 해결된다.

#### B-minor-2 오버레이 배경이 `inert`/`aria-hidden` 이 아니고, 초점이 빠지면 트랩이 새어 나간다
`useDialogFocus.ts:47-66` 의 Tab 트랩은 **초점이 이미 패널 안에 있을 때만** 작동한다(head/tail 비교 방식). `.overlay` 여백을 클릭하면 — 오버레이에 `onClick` 이 없어 닫히지도 않고 — 초점이 `body` 로 떨어지고, 이후 Tab은 문서 첫 초점 요소(스킵 링크)로 이동해 트랩 밖으로 나간다. `aria-modal="true"` 가 대부분의 스크린리더에서 배경 탐색을 막아 주므로 실사용 영향은 제한적이다.

#### B-minor-3 1024에서 시간 축 마지막 열이 잘린다
`after-1024.png` 확인. 격자 최소 폭 = 148 + 18×44 + 18×4 = **1012px**, 사용 가능 폭 ≈ 928px → 약 84px(2열분) 초과. 슬롯 44px 최소 타깃은 Critical A-2의 근거이므로 줄일 수 없고, 제작 §5가 트레이드오프로 명시했다. 스크롤바가 뚜렷이 보여 발견 가능하며, Tab 이동 시 브라우저가 자동으로 스크롤해 넣는다. **사용에 지장을 주는 수준은 아니다** — 다만 B-Major-3(방 이름 sticky)를 고치면 체감이 크게 줄어든다.

#### B-minor-4 스킵 링크가 `top` 을 트랜지션한다 (VISUAL-CRAFT §4)
`app.css:87` `transition: top var(--dur-fast) var(--ease)`. §4는 *"transform·opacity만 애니메이트 … layout·paint를 유발하는 속성(width·**top**·box-shadow 등) 금지"* 다. `transform: translateY` 로 바꾸면 끝난다. 슬롯·버튼의 `background`/`border-color` 트랜지션도 문자적으로는 paint 속성이나, 44px 요소의 120ms 호버 전환으로 실제 프레임 손실은 없다. `prefers-reduced-motion` 은 준수한다(app.css:803-810).

#### B-minor-5 오류 배너의 다음 행동 문구가 색 배경 위 회색 텍스트다
`.notice__next { color: var(--c-text-2) }` 가 `--c-danger-weak`(`#fdecec`) 면 위에 놓인다. 대비는 5.50:1로 AA를 통과하지만, `VISUAL-QUALITY.md` 기계 바닥이 별도 항목으로 세운 *"색 배경 위 회색 본문"* 패턴에 해당한다. 오버레이 아래로 들어가면 3.84:1까지 떨어진다(B-Critical-1과 복합).

#### B-minor-6 비활성 날짜 버튼의 대비가 1.71:1이다
`.btn:disabled` = `--c-text-off`(`#b4b9c4`) on `--c-surface-sunken`(`#edeff2`). WCAG는 비활성 컨트롤을 대비 요구에서 제외하므로 규격 위반은 아니다. 다만 `after-1440.png` 에서 `이전 날` · `오늘` 이 거의 배경에 녹아 있어, "왜 안 눌리는가"(= 오늘이 하한이다)라는 정보가 전달되지 않는다.

- **C-Major-2 [Major] 제작 문서 §1.2가 A-12를 해소로 기록했으나 `DateSelector` 는 여전히 가시 라벨이 없다.** A-12는 *"화면에 제목이 없고 날짜 입력에 가시 라벨이 없다"* 는 두 결함을 담고 있었다. 제목은 해결됐고 날짜 입력 라벨은 해결되지 않았다. `placeholder="YYYY-MM-DD"` 는 값이 있으면 사라지므로 라벨을 대신하지 못한다. 그리드 밖이라 `<label>` 추가에 제약이 없다(`DateSelector` 의 prop만 못 바꿀 뿐, `ReservationPage` 에 형제 `<label htmlFor>` 을 두는 것은 허용 범위다).

**Minor — 3건**

- **C-minor-1** 제작 §0 "변경 파일" 표에 `vite.config.ts` 누락.
- **C-minor-2** 제작 §1.1이 `섹션 사이 48px` 로 기록했으나 실제 섹션 간격은 **32 / 16 / 8px** 이다(`.masthead`·`.toolbar`·`.notice` 의 `margin-bottom` = `--sp-6`·`--sp-4`·`--sp-2`). 48px(`--sp-7`)은 `.shell` 의 상단 패딩이다. 리듬 요건 자체는 충족하므로 디자인 결함이 아니라 기록 오류다.
- **C-minor-3** 전략 §1.2가 Minor 7/7 완전 해결로 집계했으나 B-21은 부분이다(제작 §5가 정정). 두 승인 문서 간 불일치이며 제작 쪽이 정확하다.

**미통과** — Critical 1건(성공 기준 3 미충족, B-Critical-1과 동일 원인) / Major 2건 / Minor 3건.

## 부록 A — 실물 이미지 9장 관찰 기록

Read 도구로 직접 열어 본 내용이다. 좌표·치수는 이미지에서 읽은 값이고, RGB는 픽셀 샘플링 실측값이다.

### A.1 개선 전 2장

**`before-1440-initial.png` (945×845 콘텐츠 영역)** — 좌상단 약 450×130px에만 내용이 있고 나머지가 백지다. 최상단에 테두리 입력 상자 하나(`2026-08-28`), 라벨 없음. 그 아래 4행, 각 행이 방 이름으로 시작해 **글자 없는 회색 알약 18개**가 같은 줄에 붙는다. 1·2행 알약은 x≈70에서, 3·4행은 x≈80에서 시작한다 — 방 이름 글자 수 차이만큼 열이 어긋나 있다. 시간 축·제목·범례·헤더 전부 없다.

**`before-1440-reserved.png`** — 1행에 채워진 슬롯 1개(x≈228–330, 폭 약 102px = 빈 알약의 6배 이상). 안의 글자가 **`김본승주간 회의`** 로 붙어 있다. 이 슬롯이 넓어진 만큼 뒤 슬롯이 전부 오른쪽으로 밀려 1행은 x≈443에서, 나머지는 x≈355–364에서 끝난다 — **같은 시각의 슬롯이 방마다 다른 x좌표에 있다.**

### A.2 개선 후 7장

**`after-1440.png` (1440×900)** — 위에서부터 `회의실 예약`(28px 굵은 검정) → `2026년 8월 28일 금요일`(회청색) → 정책 1줄(연회색 13–14px) → 도구 막대(좌: `이전 날`(비활성) `2026-08-28` `다음 날` `오늘`(비활성) / 우: 범례 3종 + `16:04 기준`) → 보드 카드(흰 면, 16px 라운드, 1px 보더, 아주 옅은 그림자). 카드 안 머리 행에 `시간` + `09:00`…`17:30` 18개 눈금이 각 열 위에 정렬돼 있다. 방 4행은 이름(16px/600 검정) 아래 `20명 3층`(13px 연회색)이 두 요소로 붙는다. **09:00–16:00 열은 옅은 회색(지난 시간), 16:30–17:30 세 열만 흰색(가용)** — 16:04라는 스탬프와 정확히 일치한다. 열 어긋남 0. 카드 아래 약 290px이 여백이다.

**`after-reserved.png`** — 대회의실 16:30–18:00에 예약 1건. **3칸이 경계선 없는 하나의 회색 면**(실측 `235,237,241`)으로 이어지고, 왼쪽 위에 `구본승`(14px) / `리디자인 검수`(13px)가 2줄로 놓인다. 같은 시각 다른 방의 칸은 흰색이라 "이 방만 잡혔다"가 한눈에 읽힌다. 칸 사이 이음매·라운드 잔재가 보이지 않는다.

**`after-1024.png` (1024×768)** — 레이아웃이 그대로 좁아졌다. `:30` 눈금 라벨이 숨겨져 정시 라벨만 남는다(칸 수는 18개 그대로). 보드 카드 하단에 **가로 스크롤바**가 보이고 시간 축이 `17:0` 에서 잘린다. 방 이름 열은 아직 왼쪽에 있다(스크롤 0 위치).

**`after-390.png` (390 폭, 풀페이지)** — **축이 회전했다.** 가로축이 회의실 4곳(`대회의실`/`중회의실`/`소회의실1`/`소회의실2`, 각각 아래에 `20명 3층` 등), 세로축이 `09:00`부터 `17:30`까지 18행이다. 가로 스크롤이 없고 4개 회의실이 한 화면에 들어온다. 방 이름은 화면 어디에도 두 번 나오지 않는다. 16:30–18:00 예약이 **세로로 이어진 하나의 면**으로 렌더되고 `리디자인...` 이 말줄임된다(열 폭이 좁아 예상된 동작).

**`after-form.png`** — 배경이 `144,148,157` 로 균일하게 어두워졌다(오버레이 실측). 중앙 패널: `예약 만들기` → `2026-08-28 · 30분 단위로 최소 30분, 최대 4시간까지 잡을 수 있습니다.` → `시작 시각`(회색 채움 + 점선 보더, `16:30`) + `종료 시각`(흰 입력, `17:00`, 힌트 `09:30부터 18:00까지, 30분 단위`) 2열 → `예약자명 *` + `0 / 20`(파란 포커스 링이 뚜렷하다) → `회의 목적` + `0 / 50` + `비워 두어도 예약됩니다.` → `닫기`(흰) / `확인`(파랑). readOnly 칸이 편집 칸과 확실히 다르게 보인다.

**`after-cancel.png`** — `예약 취소` → `아래 예약을 취소합니다.` → 회색 요약 면(`회의실 대회의실` / `일시 2026-08-28 16:30–18:00` / `예약자 구본승` / `목적 리디자인 검수`) → 연한 주황 경고 면(`취소하면 이 예약은 사라지고 되돌릴 수 없습니다. …`) → `닫기`(흰) / **`확인`(빨강)**. 두 내부 면 모두 보더가 없어 카드 중첩으로 읽히지 않는다.

**`after-error.png`** — 폼이 열린 채 `구본승` / `오류 경로 검증용 입력`이 그대로 남아 있다(A-3 해결의 실물 증거). 화면 상단에 오류 배너가 있으나 **오버레이 아래에 있고**(면 실측 `149,143,150`), 다이얼로그 패널이 문장을 가로막아 `지난 시간은 예약할 수 없습니다.  오늘 남은 시간대나 이후 날짜를 선택하` 까지만 읽힌다. 패널 오른쪽의 `다시 시도` · `알림 닫기` 도 오버레이 아래다(실측 `150,154,161`). 보드 카드 상단 y좌표는 배너 없는 상태(279) 대비 283 — **이동 4px**, B-19 해결 확인.

### A.3 이번 검수가 확인하지 못한 것

- **실제 브라우저 상호작용**: 포커스 트랩·Escape·스킵 링크는 코드 전문과 오케스트레이터의 실물 검증 보고로 판정했다. 이 검수가 직접 조작하지는 않았다.
- **CDN 차단 환경의 폴백 렌더**: Pretendard가 실리지 않았을 때의 실물은 확보되지 않았다. 폴백 스택은 코드로 확인했다(`Apple SD Gothic Neo` / `Malgun Gothic` / `Noto Sans KR`).
- **다중 예약이 흩어진 격자**: 확보된 실물의 예약은 1건뿐이다. B-Major-2(가용 vs 지난 시간 단독 칸 구별)의 체감은 예약이 흩어진 화면에서 더 커질 수 있으나, 그 상태의 실물은 없다.
- **1024에서 오른쪽으로 스크롤한 상태**: B-Major-3은 CSS(`position: sticky` 0건)로 판정했으며 스크롤된 실물은 캡처되지 않았다.
