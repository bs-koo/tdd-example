## 2. 개선 계기와 목표

**계기**: 백엔드는 287건의 테스트가 지키는 4계층 구조로 완성되었으나, 프론트는 기능 동작만 확인된 상태에서 멈춰 있다. 스타일시트가 한 줄도 없어 화면이 실제 사용 가능한 형태가 아니다.

**목표**: 사내 직원이 실제로 회의실을 예약하는 도구로 쓸 수 있게 만든다. 토스 제품군에서 관찰되는 시각 언어(넓은 여백, 명확한 위계, 절제된 색, 큰 라운드, 상태의 시각적 구분)를 기준으로 화면을 재구성한다.

## 3. 성공 기준

1. **처음 쓰는 직원이 안내 없이 예약을 완료한다** — 시간 축이 화면에 표시되고, 클릭 가능한 지점이 눈에 띈다.
2. **백엔드 정책이 화면에서 사전에 드러나 오류를 줄인다** — 09–18시, 30분 단위, 최대 4시간, 14일 이내, 글자 수 제한이 입력 전에 보인다.
3. **실패 시 무엇을 고쳐야 하는지 화면이 말한다** — 오류 13종이 원인과 다음 행동을 함께 전달한다.
4. **취소 시 무엇을 취소하는지 확인된다** — 현재 취소 확인창은 예약 정보를 전혀 표시하지 않는다.
5. **격자가 무너지지 않는다** — 데스크톱 1440 / 1024, 모바일 390 폭에서 방 × 시간 정렬이 유지된다.
6. **`npm test` 108건 그대로 통과, `npm run build` 성공** — verify 게이트 무결성.

## 5.6 미해결 긴장 — hooks 불가침과 동작 결함

진단이 찾은 결함 중 **화면 계층만으로는 고칠 수 없는 것**이 있다. §5-3이 `hooks/`를 불가침으로 뒀기 때문이다.

- **A-3 (입력 소실)**: `useReservationBoard.createReservation`이 예외를 삼키고 rethrow하지 않아 호출부가 실패를 알 수 없다. 성공 여부를 알리려면 훅의 반환 계약을 바꿔야 한다.
- **B-16 (로딩 상태 부재)**: 훅에 로딩 플래그가 없어 첫 페인트가 백지다. 실패 시 재시도 수단도 없다.

전략 단계가 (a) 화면 계층 우회 (b) §5-3 개정 중 하나를 제안하고, **선택 게이트에서 사용자가 결정한다.**

## 7. 개선 강도 허용치

**시각 계층은 전면 재설계 허용, 코드 seam은 불가침.** 현재 스타일 자산이 0이므로 보존할 시각 요소가 없다 — 색·타이포·간격·레이아웃은 백지에서 정한다. 반대로 DOM 구조는 §5의 제약 안에서만 움직인다.

## 8. 제약 조건

- **스타일링 수단: 순수 CSS + CSS 변수.** 의존성 추가 없음(웹폰트 CDN link 제외). Tailwind·CSS-in-JS 도입하지 않음.
- **입력 위젯 종류를 바꿀 수 없다.** §5-1의 귀결로, 날짜는 text input, 종료 시각은 자유 입력으로 남는다. 사내 실사용 목표와 긴장이 있는 지점 — 진단 단계에서 실제 테스트 코드를 대조해 우회 가능 범위를 확정한다.
- **페이지를 늘릴 수 없다.** 백엔드 API가 회의실 조회 / 예약 조회(roomId+date) / 생성 / 취소 4개뿐이라 "내 예약 목록" 같은 화면은 데이터 원천이 없다. 단일 페이지 안에서 완결한다.
- 검증 명령: `npm test` (108건), `npm run build` (`tsc --noEmit` 포함).

## 11. [가정] — 핵심 모드 1라운드 인터뷰로 확인하지 못한 항목

- **[가정] "토스 스타일"의 해석**: 토스 앱·토스뱅크 화면에서 관찰되는 특성 — 흰색/아주 밝은 회색 배경, 파랑 계열 단일 포인트 컬러, 넓은 여백과 큰 라운드, 그림자 최소화, 굵고 큰 제목 + 작고 연한 보조 문구, 상태를 색이 아니라 면과 대비로 구분. 서체는 Toss Product Sans가 비공개이므로 Pretendard 계열로 대체.
- **[가정] 대상 환경**: 데스크톱(1440·1024) 우선, 모바일(390) 대응. 사내 도구이므로 최신 크로미움 기준.
- **[가정] 다크 모드**: 미지원(라이트 단일). 사내 예약 도구의 사용 맥락상 우선순위가 낮다고 판단.
- **[가정] 브랜드**: SQI소프트 사내 도구이나 CI 적용 지시가 없어 중립 톤으로 진행. 로고·사명 표기 없음.
- **[가정] 모션**: 상태 전환에 한정한 절제된 트랜지션. `prefers-reduced-motion` 존중.

각 가정은 이후 단계에서 사용자가 언제든 뒤집을 수 있으며, 뒤집힐 경우 해당 단계부터 재수행한다.
