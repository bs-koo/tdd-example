# reservation 용어 사전

## 예약 규칙

| 용어 | 설명 |
|------|------|
| 겹침(overlap) | 두 예약 구간이 같은 회의실에서 시간상 교차하는 상태. `A.start < B.end && B.start < A.end`로 판정 |
| 반개구간(half-open interval) | `[start, end)` 형태의 구간 표현. 끝시각과 시작시각이 같은 두 예약은 겹치지 않는다고 정의 |
| TimeSlot | 시작·종료 시각을 감싼 값 객체. `overlaps()` 판정 로직을 가진다 |
| ReservationPolicy | BR-02~BR-06(30분 단위·영업시간·길이·과거 금지·14일 제한)과 목적 길이를 검증하는 도메인 서비스. `Clock`을 주입받는다. **예약자명은 검증하지 않는다** — 로그인 사용자에게서 오므로 이미 검증된 값이다 |
| ACTIVE / CANCELLED | 예약 상태. 취소는 삭제가 아니라 상태 변경으로 처리한다 |
| Clock 주입 | `LocalDateTime.now()`를 직접 호출하지 않고 `java.time.Clock`을 주입받아, 테스트에서 `Clock.fixed()`로 시각을 고정하는 방식 |
| 예약자명(reserverName) | 예약을 만든 사람의 **표시 이름**. 로그인 사용자에게서 복사해 저장한다. **권한 판정에는 쓰지 않는다** — 취소 권한은 `memberId`로 판정한다(동명이인 문제) |

## 인증

| 용어 | 설명 |
|------|------|
| Member | 계정. 이메일이 유일 키이며 대소문자·앞뒤 공백을 지운 소문자로 정규화해 저장한다 |
| 정규화 이메일 | `Member.normalizeEmail()`이 만드는 조회 키. 가입·로그인·초대가 모두 이 값을 쓰므로 "대소문자만 다른 같은 사람"이 두 계정으로 갈라지지 않는다 |
| 불투명 토큰(opaque token) | 아무 의미도 담지 않은 256비트 난수 문자열. 세션 테이블을 가리키는 포인터일 뿐이라 위조로 권한을 만들 수 없다. JWT와 달리 로그아웃·권한 변경이 즉시 반영된다 |
| Session | 토큰 → 회원 매핑과 만료 시각. 만료 시각 **정각은 이미 만료**로 본다 |
| PasswordHasher | 비밀번호 단방향 해시 포트. 구현은 PBKDF2-HMAC-SHA256(10만 회, 계정별 솔트)이며 저장 형식은 `반복횟수:솔트:해시`. 반복 횟수를 같이 저장하므로 나중에 올려도 기존 해시를 검증할 수 있다 |
| `@LoginMember` | 컨트롤러 파라미터에 붙이면 Bearer 토큰이 가리키는 `Member`가 주입되는 애노테이션. **메서드의 첫 번째 파라미터**여야 한다 — 인증이 바디 파싱보다 먼저 판정되어야 하기 때문 |

## 그룹

| 용어 | 설명 |
|------|------|
| Group | 회의실과 예약이 귀속되는 울타리. 테이블명이 `user_group`인 것은 `GROUP`이 SQL 예약어이기 때문 |
| GroupMembership | "누가 어느 그룹에 어떤 자격으로 속해 있는가". **초대장과 멤버십을 따로 두지 않는다** — 초대는 `PENDING` 상태의 멤버십이다 |
| GroupRole | `OWNER`(그룹을 만든 사람, 초대 권한 보유) / `MEMBER` |
| MembershipStatus | `PENDING`(초대받고 미응답) / `APPROVED`(참여 중) / `REJECTED`(거절함). `APPROVED`에서 나가는 전이는 없다 — 탈퇴·강퇴는 범위 밖 |
| 재초대(reinvite) | 거절한 사람을 다시 부르는 것. 새 멤버십을 만들지 않고 기존 것을 `PENDING`으로 되돌려 이력을 한 줄로 유지한다 |
| 승인된 그룹원 | `status == APPROVED`인 멤버십을 가진 사람. 회의실 추가·조회·예약의 최소 자격이다 |
| GroupAccess | 그룹 권한 확인을 모아 둔 애플리케이션 컴포넌트. `GroupService`·`RoomService`·`ReservationService`가 **같은 규칙**을 쓰도록 한 곳에 뒀다 |
